OctaLink 개인정보처리방침

시행일: 2026-05-06 수 | 최신 개정: 2026-05-19 화 | 버전: 1.4

Unbound Apex Systems(이하 “회사”)가 제공하는 OctaLink(이하 “앱”)는 회원의 개인정보를 중요시하며, 「개인정보 보호법」 및 관계 법령에서 요구하는 사항을 준수합니다. 본 방침은 앱이 수집·이용·보관·파기하는 개인정보의 범위와 회원의 권리를 안내합니다.

요약: 본 앱은 MMA 체육관 채널별 폐쇄망 서비스로 시작합니다 (1차 채널: 'Team Posse Striking 강남점'). 외부 기관에 회원 정보를 판매·제공하지 않습니다. 향후 채널 간 합의에 따라 인접 체육관과의 교류전(Open Draw)을 단계적으로 도입할 예정이며, 교류전 시 매칭에 필요한 최소 정보(닉네임·체급·벨트·매치 결과)에 한해 채널 간 공유될 수 있습니다(회원 별도 동의 시점에 고지). 수집하는 개인정보는 회원 식별·출결·실력 평가·체급별 매치 운영 목적에 한해 사용됩니다.

2. 수집 및 이용 목적

  • 회원 식별 및 입관 승인 절차 운영 (PENDING → 관장 승인 → APPROVED)
  • 수업 출결 및 누적 출석률 산출
  • 채널 내 벨트·체급별 토너먼트 매칭, 매치 결과 및 전적 누적
  • 스킬 점수 평가 워크플로 — 코치 입력(PROPOSED) → 관장 검토 → 확정(APPROVED) 또는 반려(REJECTED)
  • 관장/코치의 한 줄 코멘트 전달
  • 수업 리마인더, 코멘트 도착 등 푸시 알림 발송
  • 체크인 시 시간/위치 검증 (선택 동의 한정)
  • 향후 채널 간 교류전(Open Draw) 운영 시 인접 체육관 채널과의 매칭 데이터 공유 — 본 기능 도입 시 별도 동의 절차 진행
  • 법령 위반 사항 및 운영 분쟁 발생 시 대응

3. 보유 및 이용 기간

  • 회원 자격 유지 기간 동안 보유. 탈퇴 또는 입관 해지 시 즉시 파기
  • 출결·매치 기록은 통계 목적으로 보존할 수 있음
  • 카카오 계정 연결 해제 알림 수신 시 PII 필드(이름·성별·이메일)는 즉시 자동 삭제 (출결·스킬·코멘트 등 운영 자료는 별도 요청 시 관장이 처리)
  • 관계 법령(전자상거래법 등)에서 별도 보존 의무가 있는 경우 해당 기간 동안 분리 보관

4. 제3자 제공 / 처리 위탁

회사는 회원의 동의 없이 개인정보를 제3자에게 제공하지 않습니다. 단, 다음의 위탁 처리는 서비스 제공을 위해 필수적입니다.

수탁자위탁 업무보유 기간
Google LLC (Firebase / FCM / Cloud Functions) 인증 토큰 보관, 푸시 알림 전송, Firestore 데이터베이스 호스팅, 서버 함수 실행 (서울 리전 asia-northeast3) 회원 자격 유지 기간
Kakao Corp. 카카오 OAuth 로그인 (현재 유일한 인증 수단) 및 카카오 비즈앱 동의 항목 제공 회원 자격 유지 기간 또는 카카오 계정 연결 해제 시점까지

채널 간 교류전 데이터 공유(예정): 향후 인접 체육관 채널과의 교류전(Open Draw) 운영을 위해 매칭에 필요한 최소 정보 (닉네임·체급·벨트·매치 결과)를 다른 체육관 채널에 제공할 수 있습니다. 본 기능은 회원 별도 동의를 받은 경우에 한해 활성화되며, 도입 시점에 본 방침을 사전 개정·고지합니다.

5. 회원의 권리

  • 본인 개인정보의 열람, 정정, 삭제, 처리 정지 요구
  • 위치정보 수집 동의 철회 (앱 설정 → 위치 권한 해제)
  • 푸시 알림 수신 동의 철회 (앱 설정 또는 OS 알림 설정)
  • 카카오 동의 항목 개별 철회 — 카카오 계정 설정에서 이메일 동의를 해제하면 해당 필드가 자동 삭제됩니다 (회원 status 는 유지)
  • 카카오 계정 연결 해제 — 카카오 계정 → 연결된 서비스 관리 → OctaLink 연결 해제 시 회원 상태가 즉시 LEFT 로 전환되고 PII 필드가 자동 삭제됩니다
  • 회원 탈퇴 요청 시 즉시 처리 (앱 내 탈퇴 메뉴 — 관장 승인 시 입관 해지 절차 병행)
  • 탈퇴 후 같은 카카오 계정으로 재로그인 시 재가입 절차 진행 (과거 출결/스킬/코멘트 등 운영 자산은 보존되어 복구 가능)

6. 개인정보의 안전성 확보 조치

  • 전송 구간 TLS 암호화
  • 인증 토큰은 OS 보안 저장소 (Android Keystore)에 보관
  • Firestore Security Rules 로 권한별 접근 제어 — 회원은 본인 문서만, 관장은 운영 전권, 코치는 입력 제안, 앱 제작자(CREATOR)는 역할 부여 권한 단독 보유
  • 관장 계정 탈취 대비 — 코치 승격(역할 부여)은 앱 제작자(CREATOR)만 가능하며 코드(RoleAllowlist.kt) + Firebase Console 두 채널 모두 통과해야 변경 가능
  • Cloud Functions 로그에 PII 출력 시 자동 마스킹 (이름 첫 글자만, uid 앞뒤 3자리만)
  • 앱 서명 키 및 서버 자격 증명은 별도 격리된 보관소에 관리
