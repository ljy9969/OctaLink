# 영업 에이전트 (sales) — 체육관 리드 인벤토리 (코드 추출 · LLM 미사용)

역할: 실제 웹 검색 결과에서 **코드가 결정적으로 추출한** 국내 격투기 체육관 리드 목록을 그대로 승인 대기(gated)로 올린다.
> 이 에이전트는 `config.json` 의 `extract` 모드로 동작한다 — **LLM 을 호출하지 않는다.** 이 문서는 사람·CEO 용 설명이다.
> (이전엔 LLM 이 리드를 "발굴"하다 `gymA.com` 같은 가짜 업체·주소를 지어내서 2026-10-16 전환.)

## 동작
1. **기본 — 카카오 로컬(장소) 검색** (`connectors/kakao-local.mjs`, 키 `KAKAO_REST_API_KEY`, 설정 `connectors/config.json` 의 `leads.sales`):
   - 대상 지역 **서울 전역**. 키워드(주짓수·종합격투기·MMA·복싱·킥복싱·무에타이·격투기)마다 서울 사각형을 검색하고,
     한 구역 결과가 API 상한(45곳)을 넘으면 4등분해 재검색(쿼드트리) → 빠짐없이 수집. 끝까지 나눠도 상한이면 리포트에 "누락 가능" 표시.
   - 주소가 '서울'로 시작하는 곳만, 장소 id 로 중복 제거.
   - 격투기 체육관 판정: 업종이 격투기·복싱/권투·무에타이·주짓수·유도 계열이면 통과. 일반 '체육관'·'헬스'·'학원'은 **이름에** 주짓수·MMA·복싱 등이 있을 때만. 태권도·합기도·검도 업종은 제외.
   - **누적 저장**(`state/sales-leads.json`: 처음 발견·마지막 확인) → 매 실행마다 **신규(🆕)** 와 이번에 안 잡힌 기존(폐업·명칭 변경 가능) 수를 표시.
   - 전체 목록 CSV(엑셀용, BOM): `exports/sales-leads-seoul.csv` — 구·체육관·업종·주소·카카오맵·신규·처음 발견·마지막 확인·교류요청.
   - **교류 요청 우선순위** (`connectors/gym-interests.mjs`, Firestore `gymInterests`): 앱 회원이 교류전 지도에서 아직 OctaLink 전인 체육관에 남긴 '교류 요청'을 읽어
     구획 맨 위에 **'교류 요청 우선 리드'** 표(요청 많은 순 · 요청 수 · 요청한 체육관 수)를 두고, 인벤토리에서도 요청 받은 리드(🤝 N)를 먼저 정렬한다 — 영업 연락 1순위.
     요청한 회원 정보는 쓰지 않는다(숫자만). 자격증명(`FIREBASE_SERVICE_ACCOUNT`)이 없거나 읽기 실패면 요청 없이 진행.
2. **폴백 — 웹 검색** (키가 없거나 카카오 호출 실패 시): `websearch.queries.sales` 로 검색 후 `extractLeads()` 가 인스타그램 계정·Tapology 체육관 페이지·지도 장소 링크만 추출(뉴스·위키·블로그·일반 웹 제외).
3. 둘 다 결과를 `context/sales.md` 의 '리드 인벤토리' 구획에 쓰고, `run-agent` 가 그 구획을 그대로 산출물로 쓴다. 검증도 코드: 구획 존재 · 6시간 이내 갱신 · 1곳 이상. 통과 시 `approvals/` 에 승인 대기.

## 하지 않는 것
- 🚫 리드를 지어내거나 기억으로 보태지 않는다(LLM 단계 자체가 없음).
- 🚫 전화번호·이메일 등 연락처를 수집하지 않는다(링크만 — 연락은 사람이 해당 공식 계정/장소 페이지에서).
- 🚫 스스로 연락·발송하지 않는다. 아웃리치 문안은 사람(Opus)이 리드를 보고 따로 작성한다.

## 산출물 형식
| 체육관 | 출처 | 링크 | 찾은 검색어 | 표 — 결론·제언 없이 목록으로 끝.
